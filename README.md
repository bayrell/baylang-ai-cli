# BayLang AI

**BayLang AI** — Python-библиотека и CLI-приложение для построения AI-агентов поверх API **OpenRouter** (OpenAI-совместимый chat-completions). Проект поддерживает диалоговый контекст, вызов инструментов модели (function calling / ReAct-цикл), резервный провайдер (fallback), сохранение и загрузку историй диалогов, prompt caching (`cache_control`) и запуск из командной строки в интерактивном и одноразовом режимах — локально или в Docker-контейнере.

---

## Возможности

- **Асинхронный HTTP-клиент** на базе `httpx`: таймауты, аккуратная обработка сетевых ошибок, никаких блокирующих вызовов в async-коде.
- **Диалоговый контекст** с ограничением длины (`trim`), очисткой (`clear`), откатом при ошибках (`truncate`) и получением последнего ответа модели (`last_response`).
- **Инструменты (function calling)**: реестр `ToolRegistry`, схемы в формате OpenAI Function Calling, выполнение вызовов модели и цикл ReAct внутри агента.
- **Fallback-цепочка**: при недоступности основного провайдера запрос автоматически выполняется через резервный.
- **Prompt caching**: в тело POST-запроса к последнему сообщению добавляется блок `cache_control: {"type": "ephemeral"}` — провайдеры, поддерживающие кеширование промпта (например, Anthropic через OpenRouter), кешируют префикс диалога и ускоряют повторные запросы.
- **Истории диалогов**: системный промпт хранится в `~/.baylang/prompt.txt`, истории — в `~/.baylang/history/` (имя по умолчанию — timestamp). При запуске история всегда чистая; сохранённые истории можно загружать по имени и просматривать список последних.
- **Два режима CLI**: интерактивный чат и одноразовый запрос `--prompt` для пайплайнов.
- **Docker**: готовый `Dockerfile` и скрипт `build.sh` (команды через `case`) для сборки, запуска и тестирования образа.
- **Безопасность**: ключ API читается только из переменной окружения и никогда не попадает в логи (в `--verbose` выводится маска).

## Установка

```bash
# клонировать репозиторий и перейти в каталог
git clone <repo-url> baylang-ai
cd baylang-ai

# создать и активировать виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Linux / macOS
# .venv\Scripts\activate         # Windows

# установить зависимости
pip install -r requirements.txt
```

Зависимости: **httpx** (HTTP-клиент) и **pytest** (тесты).

## Конфигурация

| Переменная окружения | Назначение | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | Ключ API OpenRouter (**обязательна**) | — |
| `OPENROUTER_MODEL` | Модель по умолчанию | `openai/gpt-4o-mini` |

API-ключ и имя модели хранятся **только** в переменных окружения:

```bash
export OPENROUTER_API_KEY=sk-or-...        # ключ: https://openrouter.ai/keys
export OPENROUTER_MODEL=openai/gpt-4o-mini # необязательно
```

**Приоритет значений:** аргумент командной строки → переменная окружения → значение по умолчанию.

### Домашняя папка приложения

При первом запуске создаётся каталог `~/.baylang/`:

```text
~/.baylang/
├── prompt.txt     # системный промпт (создаётся автоматически при первом
│                  #   запуске, путь переопределяется флагом --prompt-file)
└── history/       # сохранённые истории диалогов (JSON)
    ├── 20250101_120000.json   # имя по умолчанию — метка времени
    └── project-x.json         # или осмысленное имя
```

## Использование

### Интерактивный режим

```bash
python -m src.main
# или
python -m src
```

При запуске история всегда **чистая** — контекст начинается с нуля.

Диалог поддерживает команды:

| Команда | Действие |
|---|---|
| `help` | Краткая справка по командам |
| `clear` | Очистить контекст диалога |
| `model <имя>` | Сменить модель на лету (например, `model openai/gpt-4o`) |
| `save [имя]` | Сохранить историю; имя по умолчанию — метка времени (timestamp) |
| `load <имя>` | Загрузить историю из `~/.baylang/history/<имя>.json` |
| `histories` | Список последних сохранённых историй (имя, дата, размер) |
| `exit`, `quit`, `Ctrl+C`, `Ctrl+D` | Корректное завершение (код 0) |

Любая другая строка отправляется модели; контекст сохраняется между репликами, ошибки API не роняют приложение — выводится сообщение, и диалог продолжается.

Пример работы с историей:

```text
you> save
История сохранена: /home/user/.baylang/history/20250101_120000.json
you> histories
Последние истории (/home/user/.baylang/history):
  20250101_120000            2025-01-01 12:00:00  1024 байт
you> load 20250101_120000
История загружена: 6 сообщений.
```

### Одноразовый режим

```bash
python -m src.main --prompt "Скажи привет"
python -m src.main --prompt "Продолжи" --history 20250101_120000 --save
```

Удобно для пайплайнов: ответ модели выводится в `stdout`, программа завершается с кодом 0.

### Аргументы командной строки

| Аргумент | Описание |
|---|---|
| `--prompt <текст>` | Одноразовый запрос без входа в интерактивный режим |
| `--model <имя>` | Модель OpenRouter (приоритет над `OPENROUTER_MODEL`) |
| `--prompt-file <путь>` | Файл системного промпта (по умолчанию: `~/.baylang/prompt.txt`) |
| `--history <имя>` | Загрузить сохранённую историю из `~/.baylang/history/` перед стартом |
| `--save` | Сохранить историю при завершении (имя — метка времени) |
| `--list-histories` | Вывести список последних историй и завершиться |
| `--max-iters <N>` | Максимум итераций tool-calling (по умолчанию: 5) |
| `--temperature <x>` | Температура генерации (по умолчанию: 0.7) |
| `--no-tools` | Не регистрировать демонстрационные инструменты |
| `--verbose` | Подробное логирование, время ответа и статистика токенов |
| `--version` | Версия программы |

### Коды возврата

| Код | Значение |
|---|---|
| `0` | Успешное завершение |
| `1` | Ошибка выполнения (сбой провайдера, некорректный ответ) |
| `2` | Ошибка конфигурации (нет ключа, неверный аргумент, не найдена история) |

### Демонстрационные инструменты

По умолчанию агенту регистрируются два инструмента (отключаются флагом `--no-tools`):

- **`get_current_time`** — текущие дата и время на сервере в формате ISO-8601;
- **`web_search`** — заглушка веб-поиска: подтверждает запрос, не выполняя реальный поиск.

Пример диалога с инструментом:

```text
you> сколько сейчас времени?
assistant> Сейчас 2025-08-13T21:45:03.
```

## Prompt caching

Каждый POST-запрос к OpenRouter формируется с подсказкой кеширования: к последнему сообщению `messages` добавляется блок

```json
"cache_control": { "type": "ephemeral" }
```

Так провайдеры с поддержкой prompt caching (например, Anthropic через OpenRouter) кешируют префикс диалога — системный промпт и предыдущие реплики. Повторные запросы в рамках длинного диалога выполняются быстрее и дешевле за счёт кешированных, а не повторно обработанных токенов.

## Docker

В проекте есть `Dockerfile` (образ на `python:3.12-slim`) и скрипт `build.sh` с обработкой команд через `case`:

| Команда | Действие |
|---|---|
| `./build.sh build [tag]` | `docker build -t baylang-ai:<tag> .` |
| `./build.sh run [tag] [args]` | Запуск контейнера; аргументы передаются приложению, `~/.baylang` монтируется для сохранности промпта и историй |
| `./build.sh test [tag]` | `pytest -q` внутри контейнера |
| `./build.sh clean [tag]` | Удалить образ |
| `./build.sh help` | Справка |

Примеры:

```bash
export OPENROUTER_API_KEY=sk-or-...
export OPENROUTER_MODEL=openai/gpt-4o-mini   # необязательно

./build.sh build                              # сборка: baylang-ai:latest
./build.sh build 1.0                          # сборка с тегом
./build.sh run latest --prompt "Скажи привет" # одноразовый запрос в контейнере
./build.sh run --list-histories               # список историй
./build.sh run latest                         # интерактивный чат
./build.sh test                               # тесты в контейнере
./build.sh clean                              # удалить образ
```

Имя образа и тег можно переопределить переменными `IMAGE_NAME` и `IMAGE_TAG`. Тот же образ можно запустить и напрямую:

```bash
docker run --rm -it \
  -e OPENROUTER_API_KEY \
  -e OPENROUTER_MODEL \
  -v "$HOME/.baylang:/root/.baylang" \
  baylang-ai:latest
```

## Библиотека: краткий пример

```python
import asyncio

from src import Agent, OpenRouterProvider, TextMessage, Tool, ToolRegistry

async def main() -> None:
    provider = OpenRouterProvider(api_key="sk-or-...", model_name="openai/gpt-4o-mini")

    registry = ToolRegistry()
    registry.register(Tool(
        name="get_current_time",
        description="Возвращает текущие дату и время на сервере.",
        handler=lambda: "2025-01-01T00:00:00",
    ))

    agent = Agent(provider=provider, tools=registry, system_prompt="Ты helpful-ассистент.")
    agent.context.add_message(TextMessage.user("Который час?"))
    print(await agent.send())

asyncio.run(main())
```

### Ключевые классы модуля `src.ai`

| Класс | Назначение |
|---|---|
| `TextMessage` | Сообщение диалога в формате `{"role": ..., "content": ...}` |
| `Context` | Диалоговый контекст с `trim`, `clear`, `truncate`, `last_response`, JSON-сериализацией (`to_json` / `from_json`) |
| `Provider` | Абстрактный провайдер LLM (`abc.ABC`) |
| `OpenRouterProvider` | Реализация для OpenRouter: POST, SSE-стриминг, заголовки `HTTP-Referer` / `X-Title`, `cache_control` в payload |
| `Tool` / `ToolRegistry` | Инструменты агента и их реестр (function calling) |
| `Agent` | Агент с ReAct-циклом, `send`, `send_with_fallback`, `reset` |

## Troubleshooting

- **`Ошибка конфигурации: Переменная окружения OPENROUTER_API_KEY не задана`** — задайте ключ: `export OPENROUTER_API_KEY=sk-or-...` (в Docker — флаг `-e OPENROUTER_API_KEY` или `./build.sh run`).
- **`HTTP 401`** — неверный или отозванный ключ API; проверьте значение переменной окружения.
- **`Таймаут запроса`** — сеть или API OpenRouter недоступны; повторная попытка выполняется автоматически один раз.
- **`История '...' не найдена`** — проверьте имя: список доступных историй выводит команда `histories` или флаг `--list-histories`.
- **Промпт не применяется** — убедитесь, что файл `~/.baylang/prompt.txt` не пустой (или передайте путь через `--prompt-file`).
