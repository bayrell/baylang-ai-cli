# BayLang AI

**BayLang AI** — Python-библиотека и CLI-приложение для построения AI-агентов поверх API **OpenRouter** (OpenAI-совместимый chat-completions). Проект поддерживает диалоговый контекст, вызов инструментов модели (function calling) с циклом ReAct, потоковый вывод сообщений через асинхронный генератор, prompt caching, автосохранение и загрузку историй диалогов, логирование с ротацией и запуск в Docker-контейнере.

Документация для разработчиков и AI-агентов — в **[AGENTS.md](AGENTS.md)**: архитектура, ключевые классы, соглашения по коду, известные проблемы и дорожная карта.

## Возможности

- **Асинхронное ядро на `httpx`** — все сетевые операции выполняются без блокирующих вызовов, с таймаутами и аккуратной обработкой ошибок сети и HTTP.
- **Диалоговый контекст** — ограничение длины (`trim`), очистка (`clear`), откат при ошибках (`truncate`), последние сообщения (`last_messages`) и полная JSON-сериализация с сохранением tool-цепочек.
- **Инструменты (function calling)** — реестр `ToolRegistry` со схемами в формате OpenAI Function и цикл ReAct внутри агента: модель вызывает инструменты, результаты возвращаются в контекст, и так до финального ответа.
- **Потоковый вывод сообщений** — метод `Agent.send_with()` является асинхронным генератором и отдаёт текст модели, вызовы инструментов и их результаты по мере появления; CLI печатает их через единую функцию форматирования `format_display()`.
- **Истории диалогов** — контекст автоматически сохраняется в `~/.baylang/history/` после каждого ответа модели и при завершении работы; истории можно сохранять под своим именем, загружать и просматривать списком.
- **Системный промпт из файла** — хранится в `~/.baylang/prompt.txt` и создаётся автоматически при первом запуске, после чего его можно редактировать.
- **Prompt caching** — к сообщениям запроса добавляется подсказка `cache_control: {"type": "ephemeral"}`, включающая кеширование промпта у провайдеров, которые его поддерживают (например, Anthropic через OpenRouter).
- **Логирование с ротацией** — работа приложения пишется в `~/.baylang/logs/baylang.log` (до 5 бэкапов по 1 МБ), подробный режим включается флагом `--verbose`.
- **Гибкая конфигурация** — ключ API и модель задаются переменными окружения (или файлом `.env`), приоритет: аргумент командной строки → переменная окружения → значение по умолчанию.
- **Docker** — готовый `Dockerfile` и скрипт `build.sh` с командами сборки, запуска и тестирования образа.

## Установка

```bash
# клонировать репозиторий и перейти в каталог
git clone <repo-url> baylang-ai
cd baylang-ai

# создать и активировать виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Linux / macOS
# .venv\Scripts\activate         # Windows

# установить зависимости
pip install -r requirements.txt
```

Зависимости: **httpx** (HTTP-клиент), **pytest** (тесты) и **python-dotenv** (загрузка `.env`; используется в `src/main.py`, но пока не перечислен в `requirements.txt` — установите его отдельно: `pip install python-dotenv`, подробности — в [AGENTS.md](AGENTS.md)).

## Конфигурация

| Переменная окружения | Назначение | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | Ключ API OpenRouter (**обязательна**) | — |
| `OPENROUTER_MODEL` | Модель по умолчанию | `openrouter/auto` |
| `BAYLANG_SHOW_MESSAGES` | Сколько последних сообщений показывать при загрузке истории | `10` |

Ключ API и модель хранятся **только** в переменных окружения. Значения можно выгрузить в shell или положить в файл `.env` в корне проекта — он загружается автоматически через `python-dotenv`:

```bash
export OPENROUTER_API_KEY=sk-or-...          # ключ: https://openrouter.ai/keys
export OPENROUTER_MODEL=openai/gpt-4o-mini   # необязательно
```

Файл `.env` входит в `.gitignore` и **не должен попадать в репозиторий**: он содержит секреты. В логи ключ не выводится — при `--verbose` показывается только маска вида `sk-o****1234`.

### Домашняя папка приложения

При первом запуске создаётся каталог `~/.baylang/`:

```text
~/.baylang/
├── prompt.txt     # системный промпт (создаётся автоматически при первом запуске)
├── history/       # сохранённые истории диалогов (JSON)
│   ├── 1755123456.json      # имя по умолчанию — метка времени сессии (unix)
│   └── project-x.json       # или осмысленное имя
└── logs/
    └── baylang.log          # логи работы (с ротацией: 5 бэкапов по 1 МБ)
```

## Использование

### Запуск

```bash
python src/main.py
```

При запуске всегда стартует **новая сессия** с чистым контекстом; сохранённую историю можно подхватить флагом `--history <имя>`. История текущей сессии сохраняется автоматически: после каждого ответа модели и ещё раз при завершении работы.

> **Примечание:** одноразового режима (`--prompt`) в текущей версии нет — приложение запускается только в интерактивном режиме.

### Команды диалога

| Команда | Действие |
|---|---|
| `help` | Краткая справка по командам |
| `clear` | Очистить контекст диалога |
| `model <имя>` | Сменить модель на лету (например, `model openai/gpt-4o`) |
| `save [имя]` | Сохранить историю; без имени используется метка времени сессии |
| `load <имя>` | Загрузить историю из `~/.baylang/history/<имя>.json` и показать её последние сообщения |
| `histories` (алиас `list`) | Список последних сохранённых историй (имя, дата, размер) |
| `exit`, `quit`, `Ctrl+C`, `Ctrl+D` | Корректное завершение (код 0) |

Любая другая строка отправляется модели; контекст сохраняется между репликами, а ошибки API не роняют приложение — выводится сообщение, и диалог продолжается. Все сообщения (текст модели, вызовы инструментов, результаты их работы) печатаются по мере появления через единую функцию форматирования.

Пример работы с историей:

```text
you> save my-chat
История сохранена: /home/user/.baylang/history/my-chat.json
you> histories
Последние истории (/home/user/.baylang/history):
  my-chat                  2025-01-01 12:00:00  1024 байт
you> load my-chat
История загружена: 6 сообщений.
you> Привет!
assistant> Привет! Чем могу помочь?
```

### Аргументы командной строки

| Аргумент | Описание |
|---|---|
| `--model <имя>` | Модель OpenRouter (приоритет над `OPENROUTER_MODEL`) |
| `--history <имя>` (алиас `--load`) | Загрузить сохранённую историю перед стартом |
| `--show-messages <N>` | Сколько последних сообщений показать при загрузке истории (приоритет над `BAYLANG_SHOW_MESSAGES`) |
| `--list-histories` (алиас `--list`) | Вывести список последних историй и завершиться |
| `--max-iters <N>` | Максимум итераций цикла инструментов (по умолчанию: 100) |
| `--temperature <x>` | Температура генерации (по умолчанию: 0.7) |
| `--verbose` | Подробное логирование, время ответа и статистика токенов |
| `--version` | Версия программы |

### Коды возврата

| Код | Значение |
|---|---|
| `0` | Успешное завершение |
| `1` | Ошибка выполнения (сбой провайдера, некорректный ответ) |
| `2` | Ошибка конфигурации (нет ключа, неверный аргумент, не найдена история) |

## Библиотека: краткий пример

Пакет не имеет `__init__.py`, поэтому модуль импортируется как `src.ai` из корня репозитория:

```python
import asyncio

from src.ai import Agent, OpenRouterProvider, TextMessage, Tool, ToolRegistry


async def main() -> None:
    provider = OpenRouterProvider(
        api_key="sk-or-...",
        model_name="openrouter/auto",
    )

    registry = ToolRegistry()
    registry.register(Tool(
        name="get_current_time",
        description="Возвращает текущие дату и время на сервере.",
        handler=lambda: "2025-01-01T00:00:00",
    ))

    agent = Agent(provider=provider, tools=registry, max_iters=5)
    agent.context.add_message(TextMessage.system("Ты полезный ассистент."))
    agent.context.add_message(TextMessage.user("Который час?"))

    # Вариант 1: получить финальный текст ответа
    print(await agent.send())

    # Вариант 2: получать сообщения по мере появления (текст, вызовы tools, результаты)
    # async for message in agent.send_with():
    #     print(message)

    await agent.disconnect()


asyncio.run(main())
```

Исключения библиотеки: `BayLangError` (базовое), `ConfigurationError`, `ProviderError`, `ToolError`. Подробное описание классов и их контрактов — в [AGENTS.md](AGENTS.md).

## Docker

В проекте есть `Dockerfile` (образ на `python:3.12-slim`, рабочий каталог `/app`) и скрипт `build.sh` с обработкой команд через `case`. Имя образа — `bayrell/baylang-ai-command`, тег по умолчанию — `1.0.0` (можно передать свой первым аргументом).

| Команда | Действие |
|---|---|
| `./build.sh build [tag]` | Собрать образ `bayrell/baylang-ai-command:<tag>` |
| `./build.sh run [tag] [args]` | Запустить контейнер; `~/.baylang` монтируется для сохранности промпта и историй |
| `./build.sh test [tag]` | Выполнить `pytest -q` внутри контейнера |
| `./build.sh clean [tag]` | Удалить образ |
| `./build.sh help` | Справка |

Примеры:

```bash
export OPENROUTER_API_KEY=sk-or-...
export OPENROUTER_MODEL=openai/gpt-4o-mini   # необязательно

./build.sh build               # сборка: bayrell/baylang-ai-command:1.0.0
./build.sh build 1.1           # сборка с тегом 1.1
./build.sh run                 # запуск контейнера
./build.sh test                # тесты в контейнере
./build.sh clean               # удалить образ
```

Для запуска приложения с аргументами CLI удобнее прямой `docker run` (у образа нет `ENTRYPOINT`, поэтому команду приложения указывают явно):

```bash
docker run --rm -it \
  -e OPENROUTER_API_KEY \
  -e OPENROUTER_MODEL \
  -v "$HOME/.baylang:/root/.baylang" \
  bayrell/baylang-ai-command:1.0.0 python src/main.py --verbose
```

Нюансы поведения `build.sh` и ограничения текущей Docker-обвязки описаны в [AGENTS.md](AGENTS.md).

## Troubleshooting

- **`Ошибка конфигурации: Переменная окружения OPENROUTER_API_KEY не задана`** — задайте ключ: `export OPENROUTER_API_KEY=sk-or-...` или положите его в `.env` (в Docker — флаг `-e OPENROUTER_API_KEY`).
- **`HTTP 401`** — неверный или отозванный ключ API; проверьте значение переменной окружения.
- **`Таймаут запроса`** — сеть или API OpenRouter недоступны; провайдер автоматически повторяет запрос с паузой между попытками.
- **`История '...' не найдена`** — проверьте имя: список доступных историй выводит команда `histories` или флаг `--list-histories`.
- **Промпт не применяется** — убедитесь, что файл `~/.baylang/prompt.txt` не пустой.
- **Диагностика** — подробности работы приложения смотрите в логе `~/.baylang/logs/baylang.log`, а ещё детальнее — с флагом `--verbose`.
